# 선택 검사 3종 (AES-S · ALS-18 · SHAPS)

필수 7종과 달리 **선택(OPTIONAL) 검사**다. 필수 검사를 모두 마치지 않아도 응시할 수 있고, 완료한 결과는 통합 리포트 입력(PersonModel)에
자동으로 포함된다. 미응시는 "정상"이 아니라 "알 수 없음"으로 취급한다.

## 점수 체계

| 검사 | 주 점수 | 범위 | 보조/하위 점수 | 절단점 |
| --- | --- | --- | --- | --- |
| AES-S | 총점(역채점 15문항) | 18–72 | 없음 | 없음 |
| ALS-18 | 전체 평균 | 1–4 | 하위척도 평균 3개: 불안/우울(AD)·우울/들뜸(DE)·분노(ANGER) | 없음 |
| SHAPS | 차원 점수(합) | 14–56 | 이분 점수(보조) 0–14 | 이분 점수에만 있음(원판 기준 3점 이상) |

- 모든 점수는 **원점수 / 0–100 환산 / 해석 구간**을 서로 다른 값으로 저장·전달한다. 0–100 환산은 원점수가 범위 안에서 어디쯤인지 옮긴
  상대 위치일 뿐 원점수나 임상 기준이 아니다.
- 절단점이 없는 점수에는 해석 구간(band)을 만들지 않는다(`null`). "정상/비정상" 같은 라벨을 생성하지 않는다.
- SHAPS의 이분 점수와 차원 점수는 서로 변환하지 않고 각각 보존한다.

## 아직 확인하지 못한 항목 (TODO — 코드가 확정 사실로 취급하지 않는다)

### 공통
- [ ] 3종 모두 **사용 허락/저작권 조건**을 확인하지 못했다. 시드의 `license.required`는 `false`로 두었으나 이는 "확인됨"이 아니라 "미확인"이다.
- [ ] 문항 문구는 사용자가 제공한 JSX 파일을 그대로 옮긴 것이다. 원문 논문/부록과의 대조는 하지 않았다(JSX와 시드 사이의 문항·선택지·역채점·
  하위척도 배정은 자동 대조로 전부 일치함을 확인했다).

### AES-S
- [ ] 영문 원문을 바탕으로 한 **비공식 번역**이다. 한국어판의 신뢰도·타당도는 검증되지 않았다(`translationStatus: UNOFFICIAL_TRANSLATION`).
- [ ] 역채점 문항 구성(6, 10, 11번만 비역채점)을 원문 논문과 대조해야 한다.
- [ ] 자가보고판의 절단점은 연구·연령대별로 달라 사용하지 않는다(`hasCutoff: false`).

### ALS-18
- [ ] 황성훈(2015)의 번역·타당화 연구가 출처로 기재되어 있다(`translationStatus: PUBLISHED_KOREAN_VERSION`). 이는 출처 기재 기준이며, 이 앱의
  문항 문구가 논문 부록과 일치한다는 뜻이 아니다.
- [ ] 확립된 절단점이 없으므로 점수를 임상 구간으로 해석하지 않는다. 하위척도는 하나의 점수로 합쳐 해석하지 않는다.

### SHAPS
- [ ] 영문 원문을 바탕으로 한 **비공식 번역**이다(`UNOFFICIAL_TRANSLATION`).
- [ ] 이분 절단점(3점 이상)은 **원판(영어) 기준**이며 한국어 번역본에서 검증되지 않았다. 라벨은 "절단점 미만/이상"으로만 표기하고
  "정상/비정상"이라고 부르지 않는다.
- [ ] 차원 채점(Franken et al., 2007)의 방향·범위를 원문 논문과 대조해야 한다.
- [ ] 응시 시점 안내 문구("지난 며칠간")는 검사 소개 설명에만 있고 문항 화면에는 표시하지 않는다.

## AI 리포트 해석 규칙 (요약)
프롬프트(`prompt-builder.ts`, `chat-prompt-builder.ts`)에 다음이 들어 있고 `optional-assessments.guardrails.spec.ts`가 문구를 고정한다.
- AES 점수나 사용자 메모의 최근 사건으로 무기력의 원인을 단정하지 않는다.
- ALS-18 점수로 특정 기분장애(양극성장애 등)를 진단·암시하지 않는다.
- SHAPS 절단점 이상을 "비정상"이라 부르거나 우울증 진단과 동일시하지 않는다.
- 검사 간(성격검사 포함) 동시 존재만으로 인과관계를 만들지 않는다.
- 비공식 번역 검사에 의존한 주장은 확신도를 HIGH로 두지 않는다.
- 기존 "검사 사실 / 사용자 보고 / 해석 / 가설 / 알 수 없는 점" 구분 원칙을 그대로 적용한다.

## 배포 시 주의
새 검사 정의는 시드로 등록된다. 배포 후 한 번 `pnpm --filter @psyche/api prisma:seed`를 실행해야 목록에 나타난다.
